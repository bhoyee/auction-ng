# Overview analytics from application records

The owner confirmed on 2026-11-07 that the real implementation must run against seeded application records during development. Static visual-preview figures are not an analytics source. Production starts with its own database; this task does not erase any seed, wallet, bid or invoice history.

Implement PostgreSQL materialised read models through a new migration: daily metrics, category/day totals, pseudonymous distinct bidder/day membership and frozen auction outcomes. A worker refreshes these atomically every five minutes, including historical late changes, and refreshes the current operational snapshot separately. Staff requests read only these models and enforce existing per-widget permissions. Initial/missing sources are unavailable, never plausible sample figures. Time boundaries use Africa/Lagos. All money remains integer kobo with checked conversion and exact aggregation.

Auction GMV/sold counts come from frozen winning settlements at their saved auction deadline, not current leading bids or Buy Now prices. Net revenue recognises stored service charge and lot fee for paid/refunded invoices on the sale date, subtracts the exact originally stored fees on a completed full staff refund's date, and adds settled storage charges without provider fees or tax. Full staff refunds are the only implemented purchase refund workflow. Pending invoices and wallet top-ups are not revenue. Buy Now has no auction service charge. Distinct accepted buyers use one acceptance per request, not automatic-counterbid rows, and remain distinct across the selected range. Never copy private maxima, email, phone, address, BVN or authentication material into read models.

The collection funnel is a listing cohort: lots that launched in the period, then those receiving accepted bids, winning, paying and collecting. Current pickup backlog counts individual paid/uncollected lines, respecting partial collection. Operational queues use actual drafts, overdue storage cases, review withdrawals and open support tickets. Audit activity contains only action/type and timestamps, without decrypted before/after payloads. Expenses and stock valuation remain unavailable until their underlying modules exist; do not manufacture zeros or chart data for them.

The UI retains five-second silent reconciliation and event invalidation. A browser refresh cannot make a five-minute financial aggregate newer; show the real source timestamp. Current operational snapshots refresh separately and also retain their source time. Financial/report APIs never fall back to querying hot bid or ledger tables. No financial writes or auction execution rules change.

## Implemented read models and schedule

`analytics_lot_facts`, `metrics_daily`, `analytics_category_daily` and `analytics_bidder_daily` are SQL-managed materialised views with unique refresh indexes. The singleton `analytics_snapshots` holds derived operational data and separate operation/history timestamps. Schema documentation lists every column/type and index. Materialised views intentionally have no foreign keys or mutation API; all relationships originate in their source queries. Their contents are replaceable projections, not new financial records.

The existing BullMQ worker calls the private, strictly validated `POST /internal/analytics/refresh` with the existing maintenance bearer credential. Current counts refresh every ten seconds; historical aggregates refresh every five minutes, including old records affected by late changes/refunds. A transaction-scoped advisory lock admits one writer. All view refreshes and snapshot timestamps commit together; failure preserves the previous generation. Concurrent view refreshes keep readers available. Source reads have a 30-second statement timeout; the transaction/job is bounded to two minutes. No wallet or bid write/recovery path is invoked.

Actual APIs serve eight widgets: KPIs, revenue, live summary, categories, listing cohort funnel, permitted attention queues, top auction lots and redacted audit activity. The category chart combines dimensions beyond the first 49 into Other categories so totals remain conserved within the 50-row contract. Expense comparisons and stock valuation are unavailable until those modules have records. Comparison controls remain off. Net-revenue refunds use signed display formatting without weakening non-negative payment input rules.

On the local demo installation, `ADMIN_OVERVIEW_DEMO_ENABLED=false` now selects these actual read models. The same implementation works against seeded or production application records; no seeded numbers are embedded in the page. The old explicitly guarded visual-preview factory remains for isolated UI tests, not the running Overview. Production should use a clean production database without seeding, retaining local demo data separately. No data was deleted by this work.

## Validation and limits

Seventeen source/date/presentation unit tests and six isolated PostgreSQL tests pass. Database checks cover exact saved fees/GMV and full refunds, WAT boundaries, cross-day distinct bidders, no extra ledger entries, repeat refresh, concurrent writer admission, authorization/queue filtering, absent costs/expenses and a year of seeded auction dates. Ten one-year read-model requests each stay below 300ms locally; this is not an end-to-end HTTP or production-volume load benchmark. Seven focused browser cases verify actual-response display, negative refunds, source freshness, 360/768/1280px layouts and silent refresh/error/offline behavior. API, worker and admin production builds, affected package types and changed-file lint pass.

T15c remains partial: the broader metrics registry, dimension/report APIs, high-volume load validation, incremental/large-history optimisation and Redis live-stat producer are separate remaining work. Current operations use the durable PostgreSQL aggregate snapshot; five-second UI polling does not claim instantaneous financial settlement. See `docs/design/admin-overview-actual/` for captures from actual seeded read models with a synthetic staff session.

Broader root `tsc --noEmit` is not green: existing bid/recovery typing, withdrawal-test refresh-token calls, realtime return typing and native-test declarations fail. An in-memory HEAD overlay reproduced these before the actual-analytics changes. The existing Overview test's NodeList iteration issue was corrected in the touched test; unrelated failures were left unchanged. Affected package types and the new tests' targeted API-compatible type check pass. CI checks were not disabled or weakened; the full repository type debt still needs separate correction.
