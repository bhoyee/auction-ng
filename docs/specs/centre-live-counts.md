# Live pickup-centre counts

The owner selected current uncollected stock, not historical listing totals.

- **Items at centre:** current stock recorded against that centre, including drafts, upcoming/live items, unsold/cancelled stock and paid items awaiting collection. Archiving a listing does not record a physical collection, so archived stock remains included. A superseded relist source is excluded; its latest replacement is counted once. An item with a collection receipt, collected fulfilment status or collected timestamp is excluded, including legacy fully collected orders without individual receipt rows.
- **Pending pickup:** paid pickup item lines whose fulfilment is pending/booked/ready, with no collected timestamp and no individual collection record. Count items, not invoices or buyers. A partial collection reduces the total immediately for the collected lines; unpaid, refunded, cancelled and fully collected orders do not qualify. Pending items are part of Items at centre, not an additional stock total.

The existing protected `GET /staff/setup?kind=location` page returns optional typed `currentItems` and `pendingPickupItems` fields. Categories remain unchanged. The server supplies both fields for every selected centre, including zero totals. Older/missing values render a dash instead of an invented zero. `linkedLots` remains the all-history relation count used for deletion protection and must not be replaced with current stock.

One bounded aggregate query calculates both totals across the selected page of up to 50 centres, after current `setup.manage` authorization. Both metrics use the same PostgreSQL statement snapshot. Existing lot-location, settlement, invoice-line and collection keys support joins; the additive migration indexes location/type/status/collection/invoice fulfilment selection. No per-centre application query or personal buyer details are returned.

The migration also appends minimal `workspace.changed` outbox signals after fulfilment changes, individual collection inserts and stock-centre moves. Those signals commit/roll back with the source transaction and coalesce by row/transaction. The existing staff worker and Socket.IO invalidation reload the visible page silently. Five-second visible/online polling recovers missed signals; the last confirmed metrics and card stay present during silent refresh and offline states. Collection receipts, payments, refunds, holds, bidding and stock records are observed only; their workflows and money rules are unchanged. No new dependency or environment variable.

**Pickup capacity clarification:** capacity means buyers per future collection-time window. T16 booking is not active, so the field does not currently limit check-in. The centre list now shows opening hours and useful live totals instead of an unexplained per-slot figure. Editing the centre retains its existing capacity value with a clear future-booking label and explanation.

Focused verification covers empty/multiple centres, unsold and archived stock, relist deduplication, paid versus unpaid/refunded orders, partial collection, legacy full collection, unchanged ledger entries, and refresh-event transaction/rollback behaviour. Browser checks at 360/768/1280 verify silent metric changes without replacing the panel or reloading, retained offline values and the capacity explanation. See [screenshots](../design/centre-counts/README.md). T16 remains unstarted.
